# 复杂内容解释与离线可视化

你的目标不是把内容写得更长，而是让目标读者抓住：它是什么、为什么重要、如何运作、例子是什么、边界在哪里，以及下一步做什么。

## 交付契约

每次使用本技能都必须最终生成一个独立的 `.html` 文件。解释文字、图表、流程图和交互都放在该文件内；同时在回复中给出文件路径、打开方式和必要的假设。

“独立”是硬性要求：

- 文件必须包含 `<!doctype html>`、`<head>` 和 `<body>`。
- CSS 和 JavaScript 必须内嵌在同一个文件中。
- 不依赖 CDN、网络字体、外部图片、远程脚本、构建工具、框架或服务器；离线断网后仍能打开、阅读和完成核心交互。
- 图片、图标和字体优先使用文字、CSS 或内联 SVG；不能引用外部资源。
- 数据、单位、公式、示例假设和来源（如有）应直接写入页面，避免打开时还需请求接口。
- 不向用户粘贴大段 HTML 源码；交付文件本身即可。

除非用户明确要求其他格式，否则不要只输出文字说明。纯文字内容也应作为可读的 HTML 页面交付。

## 先判断，再解释

先识别三个要素：

1. 对象：概念、代码、数据、错误、流程还是图像。
2. 受众：默认是“没有技术背景但愿意理解的成年人”；若用户指定受众，以用户指定为准。
3. 目的：建立直觉、辅助决策、排查问题、学习实现，还是展示数据。

如果缺少的信息不会改变结构，就基于上述默认值继续；只有在受众、准确性或交付形式会明显改变时才提问。开始写页面前，先用不超过三句话概括已知事实，不要在尚未理解材料时先做视觉包装。

## 解释结构

按读者需要选择结构，不要机械套卡片：

- 先给一句话结论，回答“这是什么、解决什么问题”。
- 用熟悉但边界清楚的类比建立直觉；类比不能替代事实。
- 只保留理解主题所需的 3–7 个核心概念或步骤。
- 明确因果链：输入 → 发生什么 → 输出；代码说明还要指出状态、副作用和失败路径。
- 给一个小而真实的例子，展示输入、过程和结果。
- 说明不适用场景、限制、取舍、常见误解和验证方式。
- 结尾给出读者可以执行的下一步。

先讲“为什么”和“做什么”，再讲语法、API 或实现细节。首次出现的术语立即用日常语言解释。数字、单位、计算方式和不确定性必须可追溯，不能编造精确数据。

## 选择可视化

可视化只服务于理解核心关系，不为装饰增加动画或复杂度。优先选择最小的 1–2 种表达：

| 关系 | 合适表达 |
| --- | --- |
| 顺序、因果、排错 | 流程图、时间线、状态图 |
| 数量、比例、趋势 | 条形图、对比表、简图 |
| 层级、组成 | 分层结构图、嵌套模块 |
| 多方案取舍 | 对比表、决策树 |
| 代码行为 | 关键代码片段 + 行为流程 |

图表必须有标题、标签、单位或文字摘要，不能只靠颜色传达含义。若数据不足以支撑图表，使用结构化文字或流程图，并明确标注示例数据。

## 页面与交互要求

页面围绕一个明确问题组织，通常包括：标题与结论、核心模型、运作过程、例子、边界/风险、下一步，以及来源或假设（如有）。不必把所有内容做成卡片。

只有交互能帮助比较、探索或分步理解时才添加交互。每个动态交互都要有清晰反馈，并覆盖适用的状态：

- Loading：初始化或计算期间说明正在处理什么。
- Empty：没有数据或尚未选择时说明原因和下一步。
- Error：输入无效或计算失败时给出可理解的错误与恢复方式。
- Disabled：条件不足时禁用控件，并说明需要满足什么条件。

静态页面不要伪造这些状态。按钮、标签页、折叠区和图表交互应支持键盘、可见焦点和合理的 ARIA 标签；遵守 `prefers-reduced-motion`。

## 响应式与可访问性

- 先保证手机窄屏可读，再增强桌面布局；避免固定宽度导致横向滚动。
- 使用足够的文字对比度、字号和行高；信息不能只由颜色表达。
- 标题层级、按钮名称、表单标签和图表摘要完整。
- 交互在触摸、鼠标和键盘下都可用。

## 实现流程与验收

1. 阅读材料并提炼事实、受众、目的和一句话结论。
2. 选出核心关系和最小可视化表达，先排信息层级再写样式。
3. 实现单文件 HTML，所有资源内嵌，保留必要的交互和状态。
4. 验收后再交付：
   - 断网或禁用网络后直接打开文件，页面仍能渲染且核心交互可用；
   - 搜索 HTML，确认没有 `http://`、`https://`、`//` 外链、远程字体、外部脚本或外部图片引用；
   - 检查手机和桌面宽度、键盘操作、焦点、文字准确性、控制台错误和图表文字替代说明；
   - 检查 Loading、Empty、Error、Disabled，仅在确有动态交互时验收对应状态；
   - 明确告知用户已知假设、示例数据和未能验证的内容。

最终回复保持简短：提供 HTML 文件链接、打开方式、页面包含的主要内容，以及任何重要假设或验证限制。
