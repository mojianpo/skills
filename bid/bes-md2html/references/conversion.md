# 转换与模板维护

普通转换直接运行 `scripts/convert.py`，无需读取本文。只有需要修改默认排版、增加可选能力或排查转换问题时才加载。

## 默认约定

- 输入：一个 UTF-8 Markdown 文件
- 输出：必须与源文件同目录，默认同名 `.html`
- 自定义：只允许修改输出文件名，不允许修改输出目录
- 模板：仅使用 `assets/base.html`
- 依赖：优先 `markdown`，其次 `markdown2`
- 产物：单文件 HTML，CSS 内联，无网络资源

## 模板占位符

`assets/base.html` 包含三个占位符：

| 占位符 | 内容 |
| --- | --- |
| `{{TITLE}}` | 已进行 HTML 转义的文档标题 |
| `{{NAV}}` | 根据二级标题生成的左侧章节导航 |
| `{{BODY}}` | Markdown 解析器生成的正文 HTML |

不要增加第二个默认模板。需要特殊风格时，针对本次输出调整生成后的 HTML；只有用户明确要求长期复用时才扩展模板。

## 解析规则

脚本按以下顺序选择解析器：

1. `markdown`：启用 `extra`、`sane_lists`
2. `markdown2`：启用 fenced-code-blocks、tables、strike、task_list

两者都不存在时，脚本退出并提示安装命令。不要用正则表达式自行实现完整 Markdown 解析器。

## 标题规则

1. 优先使用第一个一级标题。
2. 没有一级标题时使用文件名。
3. 页面正文保留原始一级标题，不删除内容。
4. 一级标题作为文档总标题，不进入左侧章节导航。
5. 每个二级标题必须拥有唯一 `id`，并在左侧导航中生成对应链接。
6. 没有二级标题时，导航只提供“文档开头”链接。

## 输出路径规则

1. 未提供第二个参数时，`docs/report.md` 输出为 `docs/report.html`。
2. 第二个参数只含文件名时，`docs/report.md custom.html` 输出为 `docs/custom.html`。
3. 第二个参数包含目录时，仅当其解析后仍与源 Markdown 同目录才接受。
4. 输出扩展名必须是 `.html`。
5. 禁止创建与源 Markdown 不同目录的 HTML；不要绕过脚本中的路径校验。

## 默认 CSS 边界

默认模板只负责：

- 可读的字体、行高和内容宽度
- 标题、链接、引用、列表、代码块
- 使用独立滚动容器的表格；按内容自然分配列宽，并为单元格保留可读的最小宽度
- 图片自适应
- 移动端与打印样式
- 桌面端左侧二级标题导航；窄屏时移到正文上方，打印时隐藏
- 跟随系统的专业深浅配色、克制的渐变背景与清晰的卡片层级

默认模板不包含多主题变量组、浮动设置面板、JavaScript、React/Babel、动画、视觉特效或业务专属徽章。

## 按需增强

只有用户明确提出时才增加：

- 多级目录：在默认二级标题导航的基础上按需收录 `h3`。
- 代码高亮：优先使用可内联的静态高亮结果，避免 CDN。
- 品牌样式：在现有变量上调整颜色、字体和间距。
- 状态徽章：只处理用户指定的有限词表，避免误改正文。

## 降级方案

自带脚本无法运行时：

1. 检查环境是否已有 Pandoc 或其他成熟 Markdown 解析器。
2. 使用该解析器生成正文 HTML。
3. 将正文注入 `assets/base.html` 的 `{{BODY}}`。
4. 对标题做 HTML 转义后替换 `{{TITLE}}`。
5. 执行与 `SKILL.md` 相同的结构数量检查。

不要手工逐段转换大型文档。

## 验证清单

- [ ] 输出存在且大于 0 字节
- [ ] 输出 HTML 与源 Markdown 的父目录完全相同
- [ ] 包含 doctype、main 和闭合 html 标签
- [ ] 一级至六级标题数量合理
- [ ] 一级标题不进入导航
- [ ] 每个二级标题都有唯一 `id`，导航链接与其一一对应
- [ ] 表格数量与源文档一致
- [ ] 每个 `table` 都有 `.table-wrap` 容器，表格列使用可读的最小宽度且容器支持横向滚动
- [ ] fenced code block 数量与输出 `pre` 数量一致
- [ ] 链接和图片地址未被意外改写
- [ ] UTF-8 中文显示正常
