# bes-bid-report — 标书审核报告生成

## 目标

读取用户指定的审核结果文档，生成结构清晰、仅基于原始审核结果的审核报告 Markdown 和 HTML 文件。输出目录按以下规则确定：用户明确指定报告输出目录时使用该目录；否则使用审核结果文档所在目录。

## 输入门控

开始处理前必须确认以下信息：

1. 审核结果文档的有效路径。
2. 文档可以读取，且包含可用于生成报告的审核结果。
3. 项目名可以从文档内容、文件名或用户输入中确定。
4. 报告输出目录（可选）。如果用户指定，必须确认该目录有效且可写；如果未指定，使用审核结果文档所在目录。

如果路径缺失、文件不可读、项目名无法确定或审核结果为空，必须暂停并向用户说明缺失项；不得猜测路径、项目名或审核结论。

## 执行流程

### 1. 定位并读取输入

- 使用用户提供的路径读取审核结果文档。
- 记录输入文件的绝对路径、文件名和所在目录。
- 确定报告输出目录：用户指定的输出目录优先；未指定时回退到审核结果文档所在目录。记录该目录的绝对路径，并确认目录存在且可写；如用户指定的目录不存在或不可写，必须暂停并说明原因，不得静默改用其他目录。
- 保留原文中的审核结论、问题描述、证据、风险和建议；不得凭空补充事实。
- 若文档包含互相矛盾的结论，原样标记冲突，并要求用户确认；不得自行裁决。

检查点：已确认输入文件存在、可读，且项目名和审核结果可用。

### 2. 生成审核报告 Markdown

报告必须写入已确定的报告输出目录，文件名严格采用：

```text
{项目名}_审核报告_{日期}.md
```

其中：

- `{项目名}` 使用已确认的项目名；文件名中的非法字符按操作系统规则安全处理，但不得改变项目名含义。
- `{日期}` 使用执行当天日期，格式为 `YYYY-MM-DD`。

报告至少包含以下章节；没有对应内容时明确写“原审核结果未提供”，不得留空或臆造：

1. 报告基本信息：项目名、审核日期、输入文档。
2. 审核结论：直接归纳原审核结果的总体结论。
3. 主要问题：按严重程度或原文顺序列出问题、位置、证据和影响。
4. 风险与整改建议：仅整理原文已有的风险和建议，并区分事实与建议。
5. 待确认事项：列出原文中的不确定、冲突或缺失信息。

生成约束：

- 不得改变原始审核结论的方向、严重程度或适用范围。
- 不得把推测写成事实，不得补充未出现在输入文档中的法规、数据、评分或结论。
- 对原文中的表格、清单和编号，尽量保持其层级与对应关系。
- Markdown 必须可正常解析，标题层级连续，表格列数一致，代码或路径使用反引号包裹。

检查点：报告已生成，且每个结论都能追溯到输入文档或被明确标记为待确认。

### 3. 转换为 HTML

- 调用 `bes-md2html` 技能，将刚生成的审核报告 Markdown 转换为 HTML。
- 转换输入必须是本次生成的 Markdown 文件，HTML 输出必须位于与该 Markdown 文件相同的已确定报告输出目录，并保持项目名和日期对应关系。
- 如果 `bes-md2html` 不可用、转换失败或输出路径不明确，保留 Markdown 文件，报告失败原因，不得声称 HTML 已生成。

### 4. 验证输出

完成前检查：

- Markdown 文件存在且可读取。
- HTML 文件存在且可读取。
- 两个文件位于已确定的报告输出目录。
- 文件名包含已确认的项目名和执行日期。
- HTML 内容非空，且由本次 Markdown 报告转换得到。

若任一检查失败，明确列出失败项和当前已成功生成的文件。

## 输出格式

最终向用户报告：

```text
审核报告已生成。
- Markdown：{绝对路径}
- HTML：{绝对路径}
- 项目名：{项目名}
- 日期：{YYYY-MM-DD}
```

若转换或验证失败，改为说明：

```text
审核报告未完整生成。
- 已生成：{文件路径及类型}
- 失败步骤：{步骤}
- 原因：{具体原因}
- 需要用户处理：{必要操作}
```

## 禁止事项

- 不得在未获得审核结果文档路径时开始生成报告。
- 不得跳过输入校验、Markdown 生成或输出验证步骤。
- 不得虚构审核事实、评分、法规依据、项目名称或转换结果。
- 报告输出目录必须遵循以下优先级：用户明确指定的报告输出目录 > 审核结果文档所在目录。
- 用户未明确指定输出目录时，不得将报告写入与输入文档不同的目录。
- 用户明确指定输出目录时，不得擅自改用输入文档所在目录或其他目录。
