# bes-bid-review — 标书审核

## 资源与路径
先通过 `SKILL.md` 所在位置确定本技能目录为 `{SKILL_DIR}`。不要把调用者的当前工作目录当作技能目录。所有资源相对路径和输出相对路径均以 `{SKILL_DIR}` 为基准：

- 默认输出：`download/{项目名}/`
- 业务规则输出：`download/{项目名}/rules/`
- 文档解析输出：`download/{项目名}/parsing/`
- 规则审核结果输出：`download/{项目名}/results/check/`
- 合规性检查结果输出：`download/{项目名}/results/compliance/`
- 审核报告输出：`download/{项目名}/results/report/`


输出路径必须遵守以下不可跳过的约束：

1. 唯一默认输出根目录是 `{SKILL_DIR}/download/`，项目产物写入 `{SKILL_DIR}/download/{项目名}/`。
2. `--output` 的相对路径必须相对于 `{SKILL_DIR}` 解析，不得相对于调用命令时的当前工作目录解析。
3. 显式传入的绝对输出路径也必须位于 `{SKILL_DIR}` 内。
4. 禁止使用 `..`、符号链接或绝对路径把任何生成产物写到 `{SKILL_DIR}` 之外；路径越界时必须在创建目录或写文件前停止并报告错误。
5. 输入的招标文件、技术标和商务标可以位于 `{SKILL_DIR}` 之外；本约束只限制生成产物。

不要硬编码技能目录的绝对路径。

## 流程

1 首先是用户发起标书审核指令，技能会根据用户提供的招标文件、技术标和商务标进行业务规则审核和合规性检查；如果用户没有提供招标文件，提示用户提供招标文件；如果用户没有提供投标文件（技术标和商务标），提示用户提供投标文件（技术标和商务标）

2 根据用户提供的招标文件和投标文件逐个文件调用技能：`bes-document-parsing` 解析招标文件和投标文件，生成解析文档结果并持久化到对应的文档解析输出路径下。

3 根据用户提供的业务审核规则（如果用户没有提供，则用默认的业务审核规则），调用技能：`bes-bid-rule` 解析业务审核规则并持久化到对应的规则审核结果输出路径下。

4 遍历每条业务审核规则 + 解析文档结果目录，调用技能：`bes-bid-rule-review` 对单个审核规则进行审核，并将结果持久化到规则审核结果输出路径下，按照标号索引命名文件名。

5 根据解析文档结果目录，调用技能：`bes-bid-compliance-check` 进行合规性检查，并将结果持久化到合规性检查结果输出路径下（`results/compliance/`）。

6 根据审核的结果内容 + 审核报告目录，调用技能：`bes-bid-report` 生成最终的审核报告。
