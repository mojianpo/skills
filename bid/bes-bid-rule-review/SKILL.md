# 单条标书规则审核

## 目标

输入一条完整的审核规则信息和一个本地标书文档目录。围绕该规则的“关联模板”和“规则描述”进行检索与核验，最终只返回一个可解析的 JSON 对象。不得把目录中不存在或未读到的内容当作符合规则的证据。

## 输入

审核规则信息至少包含以下字段；字段缺失时，不要猜测其值：

```json
{
  "审核模块": "",
  "审核项": "",
  "审核要点": "",
  "规则名称": "",
  "风险等级": "",
  "规则类型": "",
  "关联模版": "",
  "规则描述": ""
}
```

同时需要一个明确的标书文档目录绝对路径或可解析的本地路径。目录中的文件可能是 PDF、Word、Excel、文本或其他可读取格式；按实际可用的文档读取能力处理，不要仅凭文件名下结论。

## 审核流程（Agent Loop）

严格围绕当前这一条规则循环，直到满足终止条件：

1. **校验输入**：确认规则字段和文档目录存在。记录缺失字段、目录不可访问或无法解析的文件，不要静默忽略。
2. **解析关联模版**：从 `关联模版`（输入也兼容字段名 `关联模板`）中提取模板名称、别名、章节名、关键词和可能的文件名线索。优先查找模板本身、模板映射表、目录索引和文件名；模板为空时，以 `规则描述`、`审核项`、`审核要点` 生成检索词，并标记模板未提供。
3. **检索候选文档**：在目录及其子目录中按“模板线索 → 规则名称/审核项 → 规则描述关键词”逐层检索。优先阅读最相关的文件和章节，再扩展到同一模板或同一业务章节的文档。不得只读一个候选文件后直接结束，除非已获得充分证据。
4. **提取可核验事实**：对每条证据记录文件路径、页码/章节/表格位置（能获取时）、原文摘要和与规则的对应关系。证据必须来自标书文档；推测、常识和规则描述本身不能作为标书已满足的证据。
5. **比对规则**：将证据与 `规则描述` 的每个必要条件逐项比较。对“必须/不得/至少/不低于/应包含”等约束进行明确核验；对于数值、日期、资质、人员、业绩、承诺等内容，保留原始值及单位，避免自行补全。
6. **继续 Loop**：若证据不足、候选文档存在但未定位到内容、或发现相互矛盾的证据，继续检索其他相关文件/章节并重新比对。Loop 的每轮都应缩小搜索范围或增加证据，不得重复无效检索。
7. **终止**：满足以下任一条件时结束：
   - 所有必要条件均有直接证据，且结论明确；
   - 已检查所有可关联的候选文档，仍无法证明满足或不满足；
   - 文档不可访问、不可解析或证据冲突，无法可靠判断。

## 判定规则

- `符合`：所有必要条件均被直接证据支持，且没有未解决的冲突。
- `不符合`：至少一个必要条件被直接证据否定，或文档明确缺少规则要求的内容。必须说明对应证据。
- `无法判断`：没有足够证据、文档无法读取、模板无法匹配或证据冲突未解决。不能将“未找到”直接等同于“不符合”。
- 若原有接口的 `是否符合规则` 只能使用布尔值：`符合=true`；`不符合=false`；`无法判断` 使用 `null`，并通过 `审核状态` 说明原因。

## 输出契约

最终响应只能包含以下一个 JSON 对象，不要添加 Markdown 代码围栏、解释文字或多个候选结果。字符串没有内容时使用空字符串，数组没有内容时使用空数组。

```json
{
  "审核模块": "string",
  "审核项": "string",
  "审核要点": "string",
  "规则名称": "string",
  "风险等级": "string",
  "规则类型": "string",
  "关联模版": "string",
  "规则描述": "string",
  "审核结果": {
    "审核状态": "符合|不符合|无法判断",
    "是否符合规则": true,
    "不符合原因": "string",
    "改进建议": "string",
    "证据": [
      {
        "文件路径": "string",
        "位置": "页码/章节/表格位置，无法获取时为空字符串",
        "内容摘要": "string",
        "对应条件": "string"
      }
    ],
    "检索范围": ["实际检查过的文件或目录"],
    "缺失信息": ["无法判断时列出缺失的文件、字段或证据"]
  }
}
```

输出要求：

- 顶层规则字段原样回填，不擅自改写规则含义；
- `不符合原因` 只描述已核实的事实；符合时可为空；
- `改进建议` 应对应缺失或不符合的具体条件；无法判断时建议补充要查的材料；
- `证据` 至少包含支撑结论的关键证据；无法判断时应说明已检查范围及缺口；
- JSON 必须合法：使用双引号、布尔值使用 `true/false`、无法判断时使用 `null`，不得输出尾随逗号或未转义换行。
